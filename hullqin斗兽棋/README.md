# 斗兽棋 AI 助手（Jungle / Dou Shou Qi AI Helper）

一个用于在线斗兽棋（[game.hullqin.cn](https://game.hullqin.cn)）的浏览器插件 + 本地对弈引擎：

- **油猴（Tampermonkey）插件**：💡 提示最佳走法、🤖 自动代走、📊 实时显示评估/深度/搜索量
- **Negamax 搜索引擎**：同一份引擎代码既可内嵌进浏览器插件，也可在 Node 里离线自测
- **测试与调优工具**：自对弈（`selftest300.js`）与双引擎对比（`compare300.js`），可并行跑数百局

> 仅供学习和娱乐使用。规则为 1:1 逆向自原站前端代码，与原站可能存在细微差异；请勿用于作弊或赌博场景。

## 功能特性

| 功能 | 说明 |
| --- | --- |
| 💡 提示模式 | 高亮最佳走法，信息行显示：最佳走法、局面评估、实际搜索深度、搜索节点数 |
| 🤖 自动代走 | 可只代红方 / 只代绿方 / 双方全自动 |
| ⏱ 思考时间 | 100ms ~ 5000ms 可调滑块（默认 600ms） |
| 🔍 固定深度 | 0~12 层滑块，0 = 按时间自动，>0 = 每步固定迭代 N 层 |
| 📖 迷你开局书 | 红方首步直接走「狮 62→55」（数据来自 400 局自对弈，红胜率 60.8%），避免浅层搜索乱开局 |
| 🔁 提示 = 自动 | 提示和自动代走使用相同的时间/深度设定，两者走法一致 |
| 🧪 离线测试 | 引擎不依赖 DOM 与第三方库，可在 Node 中大规模并行对弈 |

浏览器面板操作：右侧浮动面板 → 点击「💡 提示」「🤖 自动」，勾选「红方AI / 绿方AI」，拖动「思考」「深度」滑块；面板左上角 `—` 可折叠，可拖动位置。设置自动保存到 `localStorage`。

## 算法

搜索引擎基于 **negamax + α-β 剪枝 + 迭代加深**，并做了以下强化：

- **静态搜索（Quiescence）**：深度耗尽后只延伸「吃子 / 进兽穴」的交换链（上限 16 层），消除水平线效应——「弃子后连续反吃」看得清
- **置换表（Transposition Table）**：缓存局面评估，键为 `棋子布局 + 行棋方`（避免红绿回合混用），上限 30 万条
- **MVV-LVA 走法排序**：吃大子优先、进兽穴绝对优先，最大化 α-β 剪枝效率
- **重复局面规避**：对历史中出现过的局面降分并排序沉底，避免无意义来回走子
- **两种思考模式**：
  - 时间预算模式：预算内逐层加深（`DSQ_MAX_DEPTH` 上限，默认 14 层）
  - 固定深度模式：`DSQ_FIXED_DEPTH=N`，每步固定迭代 N 层、不限时（浏览器面板「深度」滑块即此模式）
- **迷你开局书**：`DSQ_BOOK=1` 时红方首步直接走「狮 62→55」

### 规则实现要点（逆向自原站）

- 鼠吃象，象不吃鼠；同级互吃（编号小者强：象狮虎豹狼狗猫鼠）
- 狮/虎可沿直线跳河（河中有棋子则被挡）；仅鼠可下水
- 敌方棋子位于我方陷阱时，任意棋子可吃；空陷阱可自由进入
- 不可进入己方兽穴；攻入对方兽穴即胜

### 参数（Node 环境变量 / 浏览器全局）

| 参数 | 说明 |
| --- | --- |
| `DSQ_FIXED_DEPTH` | >0 时固定迭代到 N 层（上限 30） |
| `DSQ_MAX_DEPTH` | 时间模式下的最大深度（默认 14） |
| `DSQ_BOOK` | `1` 启用迷你开局书（浏览器插件默认启用；Node 测试默认关闭） |

## 快速开始

### 浏览器使用（油猴插件）

1. 安装 [Tampermonkey](https://www.tampermonkey.net/)
2. 新建脚本并粘贴 `斗兽棋AI助手.user.js` 的内容（或直接导入该文件）
3. 打开 https://game.hullqin.cn 的斗兽棋对局，右侧会出现 AI 面板
4. 点击「💡 提示」看最佳走法；勾选「红方AI / 绿方AI」开启自动代走
5. 建议设置：思考时间 ≥ 2000ms，或固定深度 7~8 层（强度参考下方实测）

### 命令行自测（无需联网）

```bash
# 单引擎自对弈 300 局（每步 1000ms，并行 12 进程）
node selftest300.js --games 300 --budget 1000 --jobs 12

# 双引擎对比（前一半 B 执红，后一半 A 执红，先后手各半）
node compare300.js --games 300 --budget 1000 --jobs 12 \
  --engineA ./engine.core.js --engineB ./engine.core.bak.js
```

常用参数（两者一致）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--games` | 300 | 局数（对比须为偶数） |
| `--budget` | 1000 | 每步思考毫秒数 |
| `--depth` | 0 | 固定迭代深度（>0 时每步不限时） |
| `--cap` | 600 | 单局硬性回合上限（超过判和，防死局） |
| `--jobs` | 12 | 并行进程数 |
| `--trace N` | 0 | 记录每局前 N 步到 CSV（`--depth` 模式建议配 `--book 0`） |

对比/自对弈的判和口径（本地测试用，不完全等同原站规则）：

- 攻入对方兽穴 / 吃光对方棋子 → 该方胜
- 轮到的一方无棋可走（困毙）→ 对方胜
- 相同局面 + 相同行棋方出现 3 次 → 和（三同局面）
- 超过 `--cap` 回合未分胜负 → 和（兜底）

输出：控制台汇总 + `compare-<时间戳>/`（对比）或 `results-<时间戳>/`（自对弈）目录下的 `results.csv` 与 `summary.txt`，均已列入 `.gitignore`。

### 从源码构建插件

```bash
node build.js
```

生成 `斗兽棋AI助手.user.js`（`--mcts` 参数已弃用，不再使用）。

## 实测强度参考

2026-09-06，双引擎对比 100 局（每步 2000ms，并行 14 进程，配对：前 50 局 B 执红、后 50 局 A 执红）：

| 引擎 | 总胜率 | 执红胜率 | 执绿胜率 |
| --- | --- | --- | --- |
| **A：`engine.core.js`（增强版）** | **67%** | 76% | 58% |
| B：`engine.core.bak.js`（原始版） | 29% | 38% | 20% |

和棋 4%。即增强版（静态搜索 + 置换表）在红绿两边都有明确优势。建议浏览器里使用增强版，并配合 2000ms+ 或 7~8 层固定深度。

## 反死局改进与先后手分析（2026-09-08）

**反死局三层机制**（新增）：
1. 搜索路径重复检测——树内再遇已走过局面直接负分；
2. 根节点动态重复惩罚——按历史出现次数递增，领先方翻倍（必须求变）、落后方减轻（可接受求和）；
3. 无吃子紧迫感——超过 10 个半回合无吃子，领先方评估逐步压分（桥接层传 stalePly）。
另修复：搜索超时中止导致路径集合泄漏、后续迭代误判重复的 bug。

**改进效果**（新旧引擎 100 局 A/B，每步 300ms）：新引擎执红 76%、执绿 72%（总胜率 ~74%）；平均回合数 254 → 134；cap 死局率 2%。

**先后手 500 局自对弈结论**（最终版引擎，每步 300ms，回合上限 300）：

| 先手红 | 后手绿 | 和棋（300 回合上限） |
| --- | --- | --- |
| 240 局中 174 胜（34.8% 总 / 50.9% 决胜局） | 168 胜（33.6% 总 / 49.1% 决胜局） | 158（31.6%） |

342 局分出胜负中红绿差距 6 局（z≈0.32，p≈0.74），**统计上无显著先后手优势**——斗兽棋在引擎水平下先后手基本公平。旧引擎 500 局（回合上限 600）结论一致：48.0% vs 46.8%。先手开局推荐：虎 56→49 / 虎 56→57 / 狮 62→55。

自对弈死局规则：**300 回合（半回合计）未分胜负即判和终止**（--cap 可调），三同局面（同局面同行棋方 3 次）提前判和。
